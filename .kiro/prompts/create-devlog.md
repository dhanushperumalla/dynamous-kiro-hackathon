Generate a detailed **Development Log (DEVLOG.md)** for a software project in **professional Markdown format**, similar to an engineering diary.

### Project Inputs
- Project Name: <PROJECT_NAME>
- Project Description: <SHORT_DESCRIPTION>
- Duration: <START_DATE – END_DATE>
- Total Time Spent: <TOTAL_HOURS>
- Tech Stack: <TECH_STACK>
- Tools / AI / CLIs Used: <TOOLS_USED>
- Team Size: <SOLO / TEAM SIZE>

---

### Devlog Requirements

Structure the Devlog with the following sections and depth:

1. **Title & Metadata**
   - Project name
   - Short description
   - Duration
   - Total time spent

2. **Overview**
   - What problem the project solves
   - Overall development approach
   - Key tools or automation used

3. **Weekly Breakdown**
   - Divide work into logical weeks (Week 1, Week 2, etc.)
   - Each week should contain:
     - Day-wise logs with:
       - Date
       - Time spent (hours)
       - Tasks completed
       - Key decisions made
       - Challenges faced
       - Solutions implemented
       - Tools / prompts / automation used

4. **Milestones & Features**
   - Highlight major milestones
   - List important features implemented
   - Mention architectural or technical decisions

5. **Technical Decisions & Rationale**
   - Framework choices
   - Architecture decisions
   - Performance or scalability decisions
   - Tooling or automation benefits

6. **Challenges & Solutions**
   - Clearly list major problems
   - Explain how each was solved
   - Mention trade-offs if any

7. **Performance / Optimization (if applicable)**
   - Bottlenecks found
   - Fixes applied
   - Metrics before vs after (if available)

8. **Time Breakdown Table**
   - Present a Markdown table with:
     - Category
     - Hours
     - Percentage

9. **Tool / AI / CLI Usage Stats**
   - Number of prompts or commands used
   - Most used tools
   - Custom prompts or scripts created
   - Estimated time saved

10. **Final Reflections**
    - What went well
    - What could be improved
    - Key learnings
    - Innovation highlights

---

### Writing Style Guidelines
- Use **clean Markdown**
- Use headings (`##`, `###`)
- Use bullet points and tables
- Be concise but detailed
- Maintain a **professional engineering tone**
- Make it suitable for:
  - GitHub repositories
  - Hackathon submissions
  - Portfolio documentation
  - Open-source projects

### Output
- Return **only the Devlog.md content**
- Do NOT add explanations or commentary
- Make it realistic, structured, and impressive
